# 案例資料缺漏表

這份文件盤點目前 `client/src/data/siteContent.ts` 裡四個案例的資料現況，以及案例詳細頁範本（`WorkDetail.tsx`）需要哪些內容才能正式公開。

案例詳細頁範本目前的固定結構是：

- 頂部：專案類型 / 年份 / 負責範圍 / 案例狀態（沒有值的欄位會自動隱藏，不顯示「待確認」）
- 5 段拆解：問題 → 分析 → 過程 → 成果 → 經驗（目前四個案例共用同一套「尚未公開」的說明文字）
- 圖片區：4 個插槽（主視覺 / 排版細節 / 使用畫面 / 延伸素材），目前顯示「IMAGE MATERIAL PENDING」

建議圖片比例統一依照 `ideas.md` 的規格：首頁封面／作品列表 4:5、案例首圖 16:10 或 3:2、案例細節圖 4:5、1:1 或橫式。

## 共通建議

1. **品牌授權是剩下兩個案例的風險點**：55 廚房與炭吉刈包涉及店家品牌是否同意公開，建議在補文案之前先確認。「布有趣」的肖像原則已確認（背影／工作畫面可用，正面臉部不可用）；「長篇書籍編輯排版」案已改為抽象化呈現，不涉及授權問題，但要留意不要誤植真實內容回去。
2. **炭吉刈包資料最少**，建議優先處理基本事實確認，避免長期用骨架狀態掛在正式作品列表上。
3. 四個案例目前的 `status` 都可以誠實反映整理進度（例如「案例素材整理中」），不需要為了看起來「完成」而提早填入未確認的內容。
